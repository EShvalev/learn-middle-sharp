# learn-middle-sharp
Для проектов курса Яндекс Практикум "Продвинутая разработка на C# и .NET"

## Спринт 1, проект "Базовый REST API"
Реализовать базовый REST API с CRUD операциями на основе шаблона webapi (ASP.NET Core Web API)

## Спринт 2, проект "Обработка ошибок, LINQ и тестирование"
Доработать сервис управления событиями:
- добавить глобальный обработчик ошибок
- в метод запроса сообщений добавить фильтрацию + пагинацию
- добавить юнит тесты (связанный проект)

## Спринт 3, проект "Асинхронная обработка и отложенное выполнение"
Доработать сервис управления событиями (мероприятиями):
- добавить новую сущность Booking (бронирование)
- реализовать паттерн "быстрый ответ + отложенная обработка"
- настроить фоновую обработку бронирований
- добавить юнит тесты для новой сущности Booking

## Тестирование

### С помощью Swagger
В браузере перейти по ссылке:
- либо `https://localhost:7001/swagger/index.html`
- либо `http://localhost:5001/swagger/index.html`

### Юнит тесты
Перейти в корневую папку проекта тестов (EventApi.Tests) и запустить команду

	dotnet test

**Замечание**: Из-за особенностей хранения событий в классе EventService (статическое поле, чтобы было возможно тестирование в Swagger и Postman) юнит тесты должны выполняться не в произвольном порядке
и не параллельно, как по умолчанию они выполняются, а в определенном порядке: вначале тесты фильтрации и пагинации, затем остальные тесты не меняющие список событий, и в последнюю очередь тесты
операций типа create/update/delete. Для этого в проект добавлен пакет Xunit.Extensions.Ordering, который позволяет управлять порядком выполнения тестов с помощью атрибута [Order(N)].

## Краткое описание API
Все методы относительно корневого пути [protocol]//[host]:[port]

| HTTP метод | Путь | Параметры | HTTP Код: Назначение |
| --- | :--- | :--- | :--- |
| GET | /api/events?title=str&from=dat&to=dat | Фильтрация: [FromQuery] title: по названию, [FromQuery] from: по дате начала (>=), [FromQuery] to: по дате окончания (<=) | 200: Возвращает список событий с фильтрацией (все параметры опциональные) |
| | ...&page=int&pageSize=int | Пагинация: [FromQuery] page: номер страницы (по умолчанию 1), [FromQuery] pageSize: размер страницы (по умолчанию 10) | и пагинацией (параметры также опциональные) |
| GET | /api/events/\{id\} | [FromRoute] id: Id события | 200: Возвращает событие по Id<br/> 404: Событие не найдено |
| POST | /api/events |  [FromBody] eventDto: структура события | 201: Добавляет новое событие<br/> 422: Ошибка валидации |
| PUT | /api/events/\{id\} |  [FromRoute] id: Id события, [FromBody] eventDto: структура события | 204: Обновляет событие данными из eventDto<br/> 404: Событие не найдено<br/> 422: Ошибка валидации |
| DELETE | /api/events/\{id\} | [FromRoute] id: Id события | 204: Удаляет событие по Id<br/> 404: Событие не найдено |
| POST | /api/events/\{id\}/book | [FromRoute] id: Id события | 202: Добавляет новое бронирование для события (отложенное создание, обрабатывается в фоновом сервисе)<br/> 404: Событие Id не найдено |
| GET | /api/bookings |  | 200: Возвращает список всех бронирований по всем событиям |
| GET | /api/bookings/\{id\} | [FromRoute] id: Id бронирования | 200: Возвращает бронирование по Id<br/> 404: Бронирование не найдено<br/> |

## Модели данных

### Событие (Event)

Структура события:

	{
		"id": "guid" [auto],
		"title": "string" [required],
		"description": "string",
		"startAt": "2026-09-28T16:42:50.411Z" [required],
		"endAt": "2026-09-28T18:42:50.412Z" [required][must be: endAt > startAt]
	}

Структура ответа при запросе списка событий:

	{
		"items": [
			{
				"id": "guid" [auto],
				"title": "string" [required],
				"description": "string",
				"startAt": "2026-09-28T16:42:50.411Z" [required],
				"endAt": "2026-09-28T18:42:50.412Z" [required][must be: endAt > startAt]
			},
			... [список событий]
		],	
		"currentPage": int [номер текущей страницы],
		"onPageItems": int [количество событий на текущей странице],
		"totalItems": int [общее количество событий при заданных фильтрах]
	}

### Бронирование (Booking)

Структура бронирования:

	{
		"id": "guid" [auto],
		"eventId": "guid" [required],
		"status": "int" [required, auto],
		"createdAt": "2026-10-28T16:42:50.411Z" [required],
		"processedAt": "2026-10-28T18:42:50.412Z" [автозаполняется при Confirm/Reject]
	}

Статусы бронирования (перечисление):

	enum BookingStatus
    {
        Pending = 1,
        Confirmed = 2,
        Rejected = 3
    }

Для обработки бронирований запущен фоновый процесс, в котором организован бесконечный цикл обработки по таймеру (PeriodicTimer) с интервалом 5 сек. 
При каждом проходе: 
1. Запрашивается список бронирований в начальном статусе Pending. 
2. В цикле для каждого создается отдельный таск, в нем выполняется имитирующая задержка в 2 сек, затем перевод в статус Confirmed (подтверждено) и сохранение в хранилище.
3. Для всех тасков выполняется единый вызов ожидания Task.WhenAll.

Допустимые переходы между статусами бронирования:

	Pending -> Confirmed
	Pending -> Rejected

При выполнении допустимого перехода поле processedAt автоматически заполняется текущей датой/временем.
При попытке недопустимого перехода выбрасывается исключение BookingStatusException.

## Обработка ошибок
Ошибки перехватываются централизованно с помощью обработчика GlobalExceptionHandlingMiddleware. В нем они логируются и приводятся к единому формату ProblemDetails.

При ошибках возвращается структура:

	{
	  "status": int,      // HTTP код ошибки
      "detail": "string"  // Текстовое описание ошибки
	}
